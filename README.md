# LocalPage Factory — Kiro University Challenge 2026

Submission for the [Kiro University Challenge](https://kiro.dev/2026/university/) (take-home final
exam). Built in Kiro from the free plan: the spec came first, the tasks came from the spec, the code
came from the tasks, and every graded artifact below was produced by Kiro and committed as it was
generated.

## What it is

LocalPage Factory turns one JSON brief about a local business into one publish-ready landing page:

```
business.json  ->  out/sunrise-roofing-repair-portland.html
```

Input (name, city, primary service, optional phone/tone/reviews) produces an SEO slug, a `<title>`
within 60 characters, a `<meta name="description">` within 155 characters, a schema.org
`LocalBusiness` JSON-LD block, an FAQ block of 3–5 question/answer pairs, and a single self-contained
HTML file with inline CSS and no external requests. Every user-supplied string that reaches HTML
passes through `escapeHtml`.

## Run it

```bash
npm install
npx tsc                                  # compile to dist/
node dist/cli.js --input business.json --out out/
```

Real output from the committed sample brief:

```
out/sunrise-roofing-repair-portland.html   (5,956 bytes)
  <title>Sunrise Roofing &amp; Repair – residential roof in Portland</title>
  <meta name="description" content="Sunrise Roofing &amp; Repair offers residential roof replacement in Portland. ...">
  <script type="application/ld+json">{"@context":"https://schema.org","@type":"LocalBusiness", ...}
```

## Tests

```bash
npx vitest run
```

```
Test Files  14 passed (14)
     Tests  141 passed (141)
  Duration  3.89s
```

Six of those files are property-based suites (`*.property.test.ts`) written with
[fast-check](https://fast-check.dev/): slug, escape, meta, JSON-LD, FAQ and page assembly. Each
property is tagged with the requirement it validates, e.g.
`// Feature: localpage-factory, Property 3 … Validates: Requirements R2.2, R2.3, R2.4`.

## How the project is laid out

| Path | What it is |
| --- | --- |
| `src/types.ts` | shared input/output types |
| `src/validate.ts` | loud failure on missing required fields |
| `src/escape.ts` | the single XSS guard used by every generator |
| `src/slug.ts` | SEO slug derivation |
| `src/meta.ts` | title tag and meta description, trimmed on word boundaries |
| `src/jsonld.ts` | schema.org `LocalBusiness` JSON-LD |
| `src/faq.ts` | FAQ block generation |
| `src/assemble.ts` | the self-contained HTML page builder |
| `src/cli.ts` | the only place I/O happens |
| `src/__tests__/` | unit tests, property tests and CLI integration tests |

## How it was built

1. One request to Kiro asking for a spec produced `requirements.md` (9 numbered requirements), then
   `design.md` (architecture, data models, 20 correctness properties, error handling, testing
   strategy) and `tasks.md` (12 tasks with checkpoints). Kiro answered its own clarifying questions
   first — "new feature or bugfix", then "requirements-first or design-first".
2. Tasks 1–6 (scaffold, `escapeHtml`, `slugify`, `buildMeta`, `buildJsonLd`, `buildFaq`) with unit
   and property tests, gated on the suite after each task.
3. Tasks 8–12 (`validate`, `assemble`, `cli.ts`, CLI integration tests, final checkpoint) ending with
   a live CLI run over the committed sample brief.

Commits on `main` follow that order: scaffold and spec, then the pure functions with their tests,
then the rest of the implementation, then the Kiro configuration artifacts.
